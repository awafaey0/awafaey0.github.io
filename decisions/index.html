Architecture decisions

Each one is a bet written down with its evidence. Some were validated, some parked on data, some are still proposals.

Kkorba.ai

K-01 · korba · Apr 2026 validated

Leave Electron for Tauri 2 and the system WebView

Context
Google blocks sign-in inside embedded Chromium (disallowed_useragent), so users couldn't open Gmail or Drive in korba. And node-pty can't pass the Mac App Store sandbox.
Decision
Move to Tauri 2 with WKWebView and an explicit Safari user agent. Prove it first with a 5-day spike: renderer sealed, one success criterion per day, abort if any day fails.
Evidence
Day 3 was the whole thesis: a real Google login end-to-end. It passed on 24 Apr 2026, no OAuth fallback needed.
Consequence
Rust backend (25+ modules), native PTY, a smaller app. Accepted risk: a standing bet that Google's detection doesn't tighten.
K-02 · korba · 2026 accepted

One play engine: shared context, smart wiring

Context
Plays (multi-step agent pipelines) handed off between steps through a rigid JSON block. If step A didn't emit the exact shape, step B silently did nothing.
Decision
Retire the JSON hand-off. Run every play as one continuous agent turn, and reshape each step's output to fit the next step's input in flight.
Evidence
The silent-failure bug lived in the hand-off path itself; removing the path removes the bug class.
Consequence
Gate what the agent composes (grey dot, plain-language plan, explicit run); trust what the user saved. The difference teaches the trust model.
K-03 · korba · May 2026 accepted

No accounts first

Context
Accounts become a gravity well: every feature starts to require one.
Decision
Identity is a publisher keypair in the macOS Keychain, exportable as an encrypted file. Accounts are a power-user upgrade, never a gate.
Evidence
The test for every feature: can someone without an account publish a space, get 500 followers, and have them receive updates?
Consequence
Free tier is genuinely useful; paid tier is publisher tools (sync, analytics, vanity URLs).
K-04 · korba · May 2026 accepted

Sharing is acquisition: never tax distribution

Context
Every shared space is opened by someone who may not have korba yet.
Decision
Sharing stays free and unlimited; price the value received, not distribution. Count the loop end to end with an anonymous install id.
Evidence
Share link → download → install attribution proven end to end on real Macs, with no accounts and no database.
Consequence
Growth and monetisation run on one loop: publish → distribute → consume → count → dashboard.

Ffustat.ai

F-01 · fustat · Nov 2026 parked

Don't route the judge to a cheaper model

Context
The judge (the scorer) is a big share of model cost. Could a smaller model do it, escalating only borderline cases?
Decision
Stay on one model for critic and judge. Judge routing parked: ruled out on evidence, not vibe.
Evidence
A guarded eval on production: a Haiku-first cascade sent 83–100% of calls to Sonnet anyway, so it saved nothing. Haiku ran 2–3 points lower and noisier, but caught planted hallucinations just as well.
Consequence
The money is in routing the critic, and that can't be trusted until the judge is anchored to humans (F-04).
F-02 · fustat · Nov 2026 accepted

Two instruments: a frozen ruler and a live bar

Context
The team's taste (their "bar") is learned from live clicks. A model-swap test needs a ruler that doesn't move.
Decision
Keep them separate. The live bar steers every critique; the golden set is frozen, version-controlled, and never fed by user clicks.
Evidence
A ruler that drifts with usage can't tell you whether model C is as good as model B.
Consequence
Golden set v1: about 15 cases (real, adversarial with planted defects, and in-the-wild), growing to 20+.
F-03 · fustat · Nov 2026 proposed

Hallucination is a hard gate

Context
Screen-reference accuracy is the judge's weakest dimension, and the whole trust story.
Decision
One invented reference to an element that isn't on the screen blocks a model swap, whatever the cost saving.
Evidence
Adversarial cases plant elements that look present but aren't; a cheaper model must still not invent.
Consequence
Routing decisions lean on the hallucination gate and the comparative verdict, not the raw /30 score.
F-04 · fustat · Nov 2026 proposed

Calibrate the judge to humans before optimising it

Context
On a strong, accurate critique the baseline judge scored 21 (fail) while the cheaper model scored 26 (pass), arguably more correct.
Decision
Anchor the judge to human-labelled verdicts before making any routing claim.
Evidence
You can't calibrate a cheaper model against a baseline that is itself miscalibrated.
Consequence
Human labels become the foundation of the golden set, not optional polish.
F-05 · fustat · 2026 accepted

Personas as an ensemble, sampled for self-consistency

Context
A single synthetic user is one noisy opinion.
Decision
One read-only judge per persona for diverse viewpoints; each persona sampled 1, 3 or 5 times and folded into one score.
Evidence
The panel roll-up names what personas agree on, so agreement becomes the "fix first" list.
Consequence
Confidence scales with samples, and cost is a dial the team controls.
